# Agent information layer — implementation plan

## Objective and boundaries

The agent chooses strategy. The layer discovers capabilities, gathers ordinary player-visible evidence, preserves history, retrieves relevant mechanics and lessons, and returns compact meaningful changes with truthful uncertainty. Optimize information gained, correct decisions and end-to-end reaction time; token reduction alone is insufficient. No debug, hidden tactical information, balance changes, save manipulation or tactical reloads.

User authorized implementation, Git initialization/baseline commit, cleanup, shared mechanics knowledge and supervised validation with existing Continuance. Earlier maintenance-only/no-game notes are superseded for this task. Do not initialize a replacement game to test new-run records. All actual live calls require the existing serialized ownership/handoff protocol.

## Working method and continuity

Read AGENTS.md, this plan and HANDOFF.md on resume. Mark a phase complete only with linked evidence; keep unresolved findings in TODO.md. Before each code increment inspect current source/tests, implement bounded changes and run meaningful regressions. All live calls stay serialized; never replay uncertain mutations. Changes to tool visibility must preserve honest play. Avoid a tooling rewrite that strands the colony.

Use Markdown/JSON for authored knowledge and plans, append-only campaign evidence and rebuildable SQLite indexes for retrieval. Do not train automatic strategies from a single episode. Agents may write researched records but must attach evidence and applicability; contradictions remain discoverable.

## P8 — Gameplay usability and complete-loop speed (active)

The earlier P0–P7 milestone did not establish efficient expert play. The subsequent combat/recovery experience and independent review show that the full interface has not earned its complexity. Keep the reliability foundation, but assess it against a lightweight direct-MCP workflow. Current game pauses for this work are intentional lab pauses, excluded from routine-only timing.

Ordered corrections, delivered incrementally:

1. Compact startup/navigation: stop loading the full immutable packet and repeated raw risks by default. Keep run rules, strategy, unresolved issues, action dependencies, novel/unknown coverage flags and exact evidence pointers. Retrieve details before the relevant decision; never interpret an index as complete health/combat evidence. Preserve full immutable records and explicit full-output access. Measure the actual existing-run startup footprint.
2. Action lifecycle: distinguish durable request receipts from strategic objectives; use concrete checks for common immediate settings and accepted jobs, including supported receipt shapes. Do not label future treatment/construction completed by acceptance. Reconcile superseded orders with observed replacement and preserve genuinely lost-response uncertainty. Existing70 open general actions with no checks are failed usability evidence, not successful memory.
3. Ordinary operating loop: compose already reviewed commands, one bounded wait and required outcome observations in one host request. Keep strategy with the agent; no tactical action whitelist. Log routine metadata automatically. Backlog nonblocking development observations instead of interrupting each play step.
4. Useful continuation: demonstrate completed routine cycles under explicit current-session qualification and agent-selected predicates. New/deteriorating threats, coverage loss, unknown execution and due duties must return control. Review known conditions by evidence; do not simply disable blockers. Guarded travel/approach before close-combat automation.
5. Comparison: held-out saved situations for retrieval/mistakes, then several comparable live intervals with development paused and consistent model/safety settings. Measure wall time, decision handoffs, wait RPC time, meaningful outcomes, and event-to-review delay. No tactical save reloads or claims of improved win rate from small samples.

Acceptance: more useful play per decision with preserved reaction quality and accessible lessons. Byte reduction alone, unit tests, and individual fast RPCs do not satisfy P8. Stop adding infrastructure unless a measured decision or control bottleneck requires it. Review suggestions are advisory; authority remains the user's goals and actual evidence.
