# Runner 0.3.1: audit repairs and live colony lab

The five independent audit defects are repaired. Live testing exposed additional integration and context problems; these were fixed in the same release. The result is smaller agent-facing output, stable persistence cost across varied query scopes, and better continuity after internal monitoring. This is evidence of specific improvements, not proof of universally better decisions or faster end-to-end play.

## Measured results

| Measurement | Earlier runner | Repaired runner |
| --- | ---: | ---: |
| 30 real lab responses replayed through each formatter | 64,812 bytes | 21,410 bytes |
| Base MCP decoded content for that same sequence | 34,426 bytes | 34,426 bytes |
| 250 distinct area queries, final ingestion median | 75.26 ms | 3.24 ms |
| 5,000 distinct queries, first/final 50 median | Not measured for old runner | 4.22 / 3.55 ms |
| 5,000-query derived index | Not comparable | 20,938,752 bytes; all scopes retained |
| Unchanged synthetic status/roster output | 1,745 bytes in old structured output | 405 bytes in lean output |

The real-response replay uses about 67% less output than the previous runner and 38% less than base MCP for the captured sequence. These are compact UTF-8 byte counts, not exact model token counts. They include observation-reference overhead and exclude controller safety IDs and the monitor's internal reads. The dataset contains every call recorded by the agent-facing runner helper during the medical sequence; separate setup and monitor probes are not part of this 30-call comparison.

First reads and short receipts still have a small overhead for evidence references and classifications; not every individual response is smaller. Full reference retrieval intentionally returns detail. The stable persistence result comes from an incremental index, not deleting history or hiding disk growth behind the small .projection.json export. A simple repeated-status workload gained roughly a millisecond of local processing in an intermediate comparison; varied queries stopped becoming progressively expensive.

Across 92 non-wait live control calls during the lab, median RPC time was 6.88 ms and median local processing was 7.35 ms. These mixed-development-build timings exclude model reasoning, approvals and host orchestration; they cannot establish a reduction in total pause-to-action time. The gap metric must not be described as model thinking time.

## What changed

- **A01, actual query compatibility:** lowercase `pawn` and explicit verbose threat coverage match the real catalog. Fixtures now include the captured schema enum. Successful empty fire scans with explicit `fireCount: 0` become known-empty; missing or positive counts without rows remain unknown.
- **A02, growing projections:** a standard-library SQLite index stores latest observations by exact semantic scope and commits them with the journal replay offset. Routine views select relevant tools or attention-bearing records. Original journals/raw responses remain authority, and rebuilding does not rewrite them.
- **A03, repeated medical payloads:** condition risk cards no longer copy entire health bodies. Exact condition changes still alter the risk fingerprint. Lean CLI output removes repeated timestamps, scope descriptions, raw paths and duplicate risk assessments. Lossless list patches return changed rows when smaller than the full list; they reference a prior observation and do not claim permanent row identity.
- **A04, review scheduling:** typed review deadlines now become due; unknown-clock reviews remain visible rather than silently passing.
- **A05, index recovery:** rebuilding reconstructs action indexes; a missing individual action index can recover from the authoritative journal on lookup.
- **Additional live findings:** recognize `bleedRatePerDay`, damage deltas carried by status responses, and successful draft receipts that omit `ok:true`. Acceptance still does not prove treatment completion.
- **Continuity and return size:** monitor stops store the complete packet in a file instead of appending it to every return. Stop reasons and relevant risks remain visible. Monitor returns and handoffs reset delta baselines so subsequent agent reads do not depend on unseen internal observations.
- **Full detail remains available:** `retrieve --observation ID` always returns full evidence. `--full-output` exposes full structured metadata and risk fingerprints when needed.

## Remaining limits and next experiments

The independent guardian was tested as a real separate process during normal stop/handback. Worker death, server unreachability, OS failure and competing-controller tests were not performed live. Offline injected tests cover some failures but do not prove live scheduling behavior. A healthy multi-cycle routine interval, a new raid/combat reaction trial, new-colony startup and a real five-day illustrated chapter were not tested in this lab. No victory or win-rate improvement is claimed.

The monitor intentionally remains conservative around downed pawns and low needs. Future tuning should distinguish normal recovery/sleep from intervention needs using actual jobs, medical trajectories and explicit reviewed plans; lowering thresholds blindly would trade observability for speed. Broader performance trials should include pending construction checks, long histories with many unresolved risks, and whole agent-to-game timing. Indexed retention does not by itself prove every retrieval/verification workload is constant-cost.

The running colony remains preserved and paused between lab sessions. These fixes change support tooling only: no developer mode, debug commands, game-state editing, save reloads, balance changes or mod-file changes were used.
