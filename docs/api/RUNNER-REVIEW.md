# Runner coverage and information-loss review

Scope: installed runner 0.3.1, captured 113-tool catalog, saved response corpus, and read-only decompiled RimMolt implementation. This review makes no runtime changes. [Probe evidence](evidence/runner-probes.json) records synthetic tests; [provenance](evidence/provenance.json) binds the inspected files.

## Findings

| Finding | Evidence and consequence | Recommended next change |
| --- | --- | --- |
| Unknown fields can disappear from the agent's compact view. | `observations.compact` reduces known get_area/list_things responses to counts/terrain/recognized risks. A synthetic new top-level field or per-thing property survives raw storage but disappears from presentation with zero review signals. Mere retrievability does not ensure the agent knows to retrieve it. | Preserve unmodeled top-level fields and novel per-entity changes, with focused detail pointers. Escalate a novel shape or unexplained material change once per applicable baseline; do not repeatedly dump entire unchanged rows. |
| “Known” conflates readable JSON with modeled coverage. | `normalize` defaults to known, and `expected_fields` returns [] for many tools. The coverage object says unmodeled but `present` normally omits coverage for known observations. A synthetic get_anomaly response is presented as ordinary data with no signal that its semantics are unmodeled. | Separate transport/parse completeness, query coverage, model coverage, freshness, and semantic review. Preserve these distinctions compactly. Do not declare every unseen field dangerous, but do not let unreviewed model coverage silently authorize unattended continuation. |
| Capability classification covers less than half the catalog by default. | `control.effect(tool,{})` yields 64 unclassified, 24 inspection-pausing, 3 inspection-ui, 19 mutation, 1 advance, 2 denied. This is a default tool-level probe, not validation of an empty argument call. Argument branches and run-local classifications can change the result. | Keep a complete discoverable capability inventory and review relevant tools before use. Prioritize surgery, trade, policy, caravan/world travel, and DLC tools. Do not bulk-classify everything as a read based on its name. |
| Outcome templates are narrow, but explicit checks already escape the template list. | `outcomes.contract` supports movement, rescue, equipment, construction, extinguishing and treatment. `validate_check` accepts arbitrary tool/field paths with supported predicate operators. `Control.call` tracks a durable action only for a non-general family, explicit check, or advance; general mutations otherwise have a request journal but no pending outcome record. | Treat family templates as conveniences. Record intended effects and evidence requirements for any consequential action, including dynamic UI work. Preserve unresolved/failed/interrupted outcomes and side effects. An unknown family should prompt an explicit verification plan, not make the strategic option disappear. |
| Current event handling is broader than a strict outcome whitelist, but still incomplete. | `safety.signals` escalates unknown `_delta` keys and unfamiliar notification structures. The positive-control probe confirms a novel delta becomes an unknown-risk signal. It separately uses recognized health/need/thing fields and ignores four resource/building delta categories as danger signals. Source shows that events themselves are incomplete. | Retain this useful open-ended event path, extend it to unknown response structure and unexpected material changes, and combine it with periodic state reconciliation. Important strategic changes need not be “danger” to deserve attention. |
| Fixed summaries can conceal strategic opportunity as well as danger. | Large research/recipe/architect lists become counts/pointers. A similar list_quests branch is dormant because that tool is absent from this catalog; actual get_world quest data follows the generic full-data path. Spatial rows lose quantities, positions and properties. A new quest, unlocked technology, scarce component or failed build is relevant to victory even if no critical alert fires. | Route changes against active goals, dependencies, unresolved problems and remembered lessons. Retrieve a changed relevant list or entity before deciding. Do not gate attention solely on predefined threat labels. |
| A legitimate compact API mode is rejected as incomplete. | Source ListThings returns groups in summary mode, while runner expected_fields always requires things. The source-shaped offline probe is marked partial with missing things. This is a concrete source/runner mismatch, not live proof of a complete summary query. | Model summary and entity-list coverage separately. A complete aggregate is still insufficient for spatial threat coverage; do not simply treat all summaries as interchangeable with full rows. |
| Input schema coverage is not output coverage. | Catalog declarations have no outputSchema or annotations. Descriptions contain behavioral constraints absent from JSON Schema; the runner's strict top-level argument validator may be narrower than the server's permissive argument extraction. Dynamic menu/gizmo values come from actual UI state. | Keep exact input contracts, textual constraints and source/observed output evidence distinct. Display newly discovered tools and schema changes. Use reviewed action-specific effect rules for mixed read/write interfaces. |

The 64 unclassified tools include normal gameplay functions such as `list_surgeries`, `add_surgery`, `list_trade`, `set_trade`, `trade_action`, `form_caravan`, `list_world_objects`, `get_world_tile`, `list_genes`, `list_mechs`, `get_anomaly`, and `get_royalty`. See the machine classification map in [probes](evidence/runner-probes.json) for the complete list. Some are deliberate setup-only or external-chat capabilities; unclassified does not imply they should all be enabled for this colony. Conversely, several names in the runner's built-in lists do not occur in the captured catalog. Catalog membership and runner policy are separate checks.

## Design direction

Use an open observation model with reviewed execution permissions. Preserve complete evidence; compact changes with named baselines; expose missing coverage, novelty, unexplained changes and unresolved intentions. Let the agent reason about any observed situation and choose an appropriate verification plan. Keep forbidden gameplay operations and hidden information constrained by the player's rules. This avoids equating “not in a template” with “irrelevant,” without turning unknown responses into permission to act blindly.

The routine packet should contain current threats, material changes/opportunities, unfinished actions, dependencies, relevant lessons and uncertainties. It should not contain this whole API manual. A small capability index plus tool-specific retrieval provides breadth when reasoning needs it. Raw values remain run-local; API shape evidence and interface constraints are reusable only with version/provenance checks.

Evaluate changes on held-out saved responses and controlled live situations. Measure missed meaningful changes and opportunities, false interruptions, successful detection of unfamiliar shapes, correct action completion, useful lesson retrieval, agent-facing output size, and time from observation to useful play. Include new DLC/quest/UI variants and failures, not just outcomes the implementation already handles. A schema field list or passing fixture suite cannot establish intelligent play or a legitimate victory.

## Follow-up order

1. Fix the demonstrated loss of unknown fields and make model coverage visible without repeating raw data.
2. Build targeted capability/effect coverage from the complete inventory; retain action-dependent behavior and normal gameplay restrictions.
3. Improve generic intention/outcome tracking and goal-aware change routing, using explicit checks where templates do not fit.
4. Validate incremental changes against the paused colony only after following the existing control handoff. Broader state checks must compensate for source event limits.

These are reviewed recommendations, not claims that the fixes have already shipped. The running game was left undisturbed.
